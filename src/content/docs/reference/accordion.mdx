## Usage guidelines
### Use this component for:

<IconList>
    <IconListItem icon="check">
        **If users will only need a few specific pieces of content within a page.**
    </IconListItem>
    <IconListItem icon="check">
        **If you have only a small space to display a lot of content.**
    </IconListItem>
</IconList>

### Use something else for:

<IconList>
    <IconListItem icon="close">
        **Make the entire header selectable.** Allow users to click anywhere in the header area to expand or collapse the content; a larger target is easier to manipulate.
    </IconListItem>
    <IconListItem icon="close">
        **If there is not enough content to warrant condensing.** Accordions increase cognitive load and interaction cost because users have to make decisions about what headers to click on.
    </IconListItem>
    <IconListItem icon="close">
        **Tables, diagrams, or complex information.** In-depth informational content such as data tables or infographics don't work well inside accordions due to their cognitive load and likelihood of multiple scrolling behavior. These should be placed outside of accordions on a page. 
    </IconListItem>
</IconList>

### Requirements for use:

<IconList>
    <IconListItem icon="report">
        **Make the entire header selectable.** Allow users to click anywhere in the header area to expand or collapse the content; a larger target is easier to manipulate.
    </IconListItem>
    <IconListItem icon="report">
        **Give interactive elements enough space.** Make sure interactive elements within the collapsible region are far enough from the headers that users don't accidentally trigger a collapse. (The exact distance depends on the device.)
    </IconListItem>
</IconList>

## Accessibility guidance
Use the [USWDS accordion accessibility tests](https://designsystem.digital.gov/components/accordion/accessibility-tests) to test accordion implementation.
- **Leverage semantic HTML before turning to ARIA** Much of the accessibility and functionality of the accordion is provided by the semantic `<details>` and `<summary>` elements. Attributes like `aria-expanded` and `aria-controls` are not necessary when using these elements.
- **Expansion is driven by the open attribute.** To programmatically open or close accordion sections, use the open boolean attribute on the `details` element rather than using `hidden` or setting `aria-expanded`.

## Code 

### Guidance 
- **Controlling accordion group behavior with `name`.** Including the same `name` attribute on multiple `<detail>` elements will allow one accordion in the group to be open at once and excluding the `name` attribute will create a multiselectable accordion group.
- **Default an accordion button to open.** Add the `open` attribute to any `usa-accordion__button` to have that section open by default at page load.
