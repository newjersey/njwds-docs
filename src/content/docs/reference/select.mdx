## Usage guidelines

### Use this component for:
<IconList>
    <IconListItem icon="check">
        **Use sparingly.** Use the select component only when a user needs to choose from about seven to 15 possible options and you have limited space to display the options.
    </IconListItem>
</IconList>

### Use something else for:
<IconList>
    <IconListItem icon="close">
        **Fewer than seven options.** Use [radio buttons](https://grove.nj.gov/reference/radiobutton/) instead.
    </IconListItem>
    <IconListItem icon="close">
        **More than 15 options.** If the list of options is very long, you could consider using a [combo box](https://grove.nj.gov/reference/combobox/), but proceed with caution as there are known accessibility issues with that component.
    </IconListItem>
    <IconListItem icon="close">
        **Multi-select.** If you need to allow users to choose more than one option at once. Users often don’t understand how to choose multiple items from select elements. Use [checkboxes](https://grove.nj.gov/reference/checkbox/) instead.
    </IconListItem>
    <IconListItem icon="close">
        **Site navigation.** Use the navigation components instead, such as the [header](https://grove.nj.gov/reference/header/), [breadcrumb](https://grove.nj.gov/reference/breadcrumb/), [side navigation](https://grove.nj.gov/reference/sidenavigation/), or [in-page navigation](https://grove.nj.gov/reference/inpagenavigation/).
    </IconListItem>
</IconList>

## Requirements for use:
<IconList>
    <IconListItem icon="report">
        **Make sure to test.** Test select menus thoroughly with members of your target audience. Several usability experts suggest they should be the “UI of last resort.” Many users find them confusing and difficult to use.
    </IconListItem>
    <IconListItem icon="report">
        **Avoid dependent options.** Avoid making options in one select menu change based on the input to another. Users often don’t understand how choosing an item in one impacts another. See [conditional fields pattern](https://grove.nj.gov/patterns/conditionalfields/) for more guidance.
    </IconListItem>
    <IconListItem icon="report">
        **Use a good default.** When most users will (or should) pick a particular option, make it the default: `<option selected="selected">Default</option>`
    </IconListItem>
    <IconListItem icon="report">
        **Avoid auto-submission.** Don’t use JavaScript to automatically submit the form (or do anything else) when an option is chosen. Offer a “submit” button at the end of the form instead. Users often change their choices multiple times. Auto-submission is also less accessible.
    </IconListItem>
</IconList>


## Content guidelines
- **Always use a label.** Make sure your select element has a label. Don’t replace it with the default menu option (for example, removing the “State” label and just having the menu read “Select a state” by default).
- **Make sure to test.** Test select menus thoroughly with members of your target audience. Several usability experts suggest they should be the “UI of last resort.” Many users find them confusing and difficult to use.
- **Use a good default.** When most users will (or should) pick a particular option, make it the default: `<option selected="selected">Default</option>`

## Accessibility guidance
Use [USWDS select accessibility tests](https://designsystem.digital.gov/components/select/accessibility-tests) to test implementation.
- **Customize form controls accessibly.** If you customize this component, ensure that it continues to meet the [accessibility requirements that apply to all form controls](https://designsystem.digital.gov/components/form).
- **Always use a label.** Make sure your select element has a label. Don’t replace it with the default menu option (for example, removing the “State” label and just having the menu read “Select a state” by default).
- **Avoid auto-submission.** Don’t use JavaScript to automatically submit the form (or do anything else) when an option is selected. Auto-submission disrupts screen readers because they select each option as they read them.
- **Avoid dependent options.** Avoid making options in one select menu change based on the input to another. Users often don’t understand how choosing an item in one impacts another.
