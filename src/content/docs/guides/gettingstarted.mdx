## Expectations of use
 
Grove is recommended for all new State of NJ projects. Teams make the final decision on adoption, though some projects may go through governance review. Even when Grove components aren't used, we encourage following Grove's design principles (like clearly distinguishing between primary, secondary, and tertiary actions).

For more information please see the full [Grove Expectations of Use documentation](https://docs.google.com/document/d/1-joZiqTQxy-WwcfT2GQwEx3a6oou4bimfWaCHEFMo3o/edit?usp=sharing).

### Missing something in the design system? 

Check out the Support and Contributions page for more information on how you can request or contribute components to the design system. 

## Required components 

### Why have required components? 
Required components provide a consistent look and feel across New Jersey State Government websites and digital services that builds trust and credibility with the public.

### Which components are required? 
- Banner: Indicates that a website is an official New Jersey State Government site
- Feedback widget: Standardized way of collecting user input on digital services and websites
- Footer: Identifies the department that owns the digital service or website
- Identifier: Official New Jersey State wrapper that links back to main NJ websites

### Getting started for engineers

#### What you'll need to get started

- Node.js (see `.nvmrc` for the project's recommended version)
- npm
- Access to the [NJWDS GitHub repository](https://github.com/newjersey/njwds)
- Familiarity with [USWDS](https://designsystem.digital.gov/) is helpful but not required

#### Setting up your first project

Grove is published as `@newjersey/njwds` on npm. Install it in your project:

```bash
npm install @newjersey/njwds
```

##### Add the stylesheet

**HTML project:** link the CSS in your `<head>`:

```html
<link rel="stylesheet" href="[path/to/styles.css]" />
```

**React (or any JS bundler):** import the CSS in your app entry point (e.g. `main.tsx`):

```js
import "@newjersey/njwds/dist/css/styles.css";
```

##### Add the JavaScript

> **React projects:** The Grove JavaScript is not currently integrated for React. Import only the CSS 
> above and implement interactive component behavior as needed on your project.

For plain HTML projects, interactive Grove components (accordions, modals, etc.) require two scripts.

Add `uswds-init.min.js` in the `<head>` — it prevents a flash of unstyled content while the page loads:

```html
<head>
  <script src="[path/to/uswds-init.min.js]"></script>
</head>
```

Add `uswds.min.js` before the closing `</body>` tag:

```html
  <script src="[path/to/uswds.min.js]"></script>
</body>
```

##### Use a component

Grove extends USWDS. Most components use USWDS HTML markup with NJ-specific CSS classes layered on top. 
Browse available components in [Storybook](https://storybook.grove.nj.gov) and each story shows the 
markup you need.

#### Best practices

- **Use USWDS utility classes** for spacing, color, and typography instead of writing custom CSS. The 
full utility list is in the [USWDS documentation](https://designsystem.digital.gov/utilities/).
- **Don't detach components.** Use components as documented. Modifying component internals breaks future 
upgrades and may introduce accessibility regressions.
- **Reference Storybook** before building anything new the component you need likely already exists.
- **Check WCAG 2.2 AA compliance** for any custom markup you add around components. The design system 
handles accessibility within its components; your surrounding HTML is your responsibility.

#### Warning signs in a project

These patterns indicate someone has gone off-script and may cause maintenance or accessibility problems:

- Hardcoded hex color values instead of classes or variables
- Fixed pixel dimensions (`width: 400px`) instead of responsive classes
- Custom-built components that duplicate existing USWDS/Grove components
- Overriding component styles by targeting internal CSS class names
- Inline styles on component elements
- (On static implementations) JavaScript that manually manipulates component state instead of using the component's built-in API

- **GitHub Issues:** [github.com/newjersey/njwds/issues](https://github.com/newjersey/njwds/issues) — bug reports and feature requests

### Getting started for designers

#### What you'll need to get started

- A full seat in Figma
- Familiarity with [USWDS](https://designsystem.digital.gov/) is helpful but not required

#### Setting up your first project

##### Adding Grove as a library in Figma 

###### Internal 
- Ensure you are part of the NJIA organization and team in Figma
- Create a project in Figma 
- Create a design file in that project 
- Go to "Actions" in the bottom toolbar and search for "Libraries" 
- Grove and USWDS should already be attached as libraries 

###### External 
- Go to the [Grove Figma Community File](https://www.figma.com/community/file/1409316805539440855)
- Click "Open in Figma" 
- In the dropdown next to the file name click "Publish library" 
- Once it is published, you can add this to any design file as a library using the Actions > Libraries in the bottom toolbar

##### Using Grove components in your designs
- Go to the assets menu in the left sidebar of your Figma file 
- Click on the Grove library 
- You can now drag in any of the assets from the design system 
- Each component has built-in settings that can be accessed in the component panel, which are presets mirroring each component's capabilities in code as well (ex: states, modes, labels, etc.) 
- **Note:** In NJIA projects, the banner, header, feedback widget, footer, and identifier are required components 

##### Using Grove variables and styles in your designs 

###### Dimensions 
- Variables are available in Grove's Figma library for: padding, margin, space between, width, height, line length, and corner radius.
- These variables are accessible in the dimensions panel in the right sidebar in Figma when you have selected an object. 

###### Color 
- Variables are available in Grove's Figma library for: theme colors, state colors, and system colors 
- These variables are accessible in the the fill, stroke, and selection panels in the right sidebar when an object is selected. 

###### Typography 
- Type styles are set up in Grove's Figma library using the themed typography settings in Grove. 
- These styles can be accessed in the typography panel in the right sidebar when a textbox is selected. 


#### Best practices

##### Refer to documentation for component and style usage guidance 
Each component and style page has detailed guidance on when and how each component is meant to be used, as well as the built in variations it has. Check that out to ensure you’re using them correctly in your designs. 

##### Required components 
In NJIA projects, the banner, header, feedback widget, footer, and identifier are required components, so make sure to start with those to ensure consistency and trust across projects.

##### Variables versus values
Whenever possible, use variables and styles rather than custom values for color, type, dimensions, etc. This will ensure that the values being used reference preset values in the design system that will make your designs easier to hand off, implement, and maintain for engineering. It will also ensure consistency within your design and across designs. 

##### Detaching components
As much as possible, avoid detaching components. The settings built into the Figma component mirror the technical capabilities of components in code. Deviations from this will require custom engineering effort and will be more difficult to maintain. 

That being said, when there are use cases that are needed for projects that are not covered, reach out to the Grove team about options! It is useful information when components have missing use cases and this helps us prioritize our roadmap. 

Custom and modified components can be built, but should be done so in collaboration with your engineers and the design system team.
